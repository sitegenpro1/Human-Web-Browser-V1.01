# PRD: Human Web Browser — Replit Buildathon MVP

**Product Name:** Human Web Browser  
**Build Target:** Replit 24-hour Buildathon MVP  
**Platform:** Mobile-first PWA / Website  
**Tech Stack:** React + TypeScript + Vite  
**Backend:** None for MVP, local-first only  
**Paid APIs:** Not allowed  
**Search Engine:** Google by default using Web Mode parameter `udm=14`  
**Core Promise:** Search Google without AI clutter, track AI-slop reports, and warn users about community-reported low-quality domains.

---

## 1. One-Line Product Pitch

Human Web Browser is a mobile-first AI-free search launcher that opens Google in Web Mode by default, lets users report AI-slop websites, and shows community-style reputation warnings for suspicious domains.

---

## 2. Replit Buildathon Goal

Build a polished, demo-ready web app on Replit that proves the idea without needing paid APIs, custom search engines, big hosting, scraping, or complex backend infrastructure.

The MVP should be:

- Easy for Replit Agent to build.
- Reliable and hard to crash.
- Mobile-first.
- Installable as a PWA.
- Local-first.
- Demo-ready within 24 hours.
- Expandable later into Android app / APK.

---

## 3. What This MVP Will Do

### 3.1 Main Capabilities

1. User searches from Human Web Browser.
2. App opens Google search with `udm=14` to prefer classic Web results.
3. User can check a website/domain reputation.
4. User can report websites as AI-slop, SEO spam, fake support, scam, misleading, or low quality.
5. App stores reports locally.
6. App combines local reports with seeded demo community data.
7. App shows domain risk tier:
   - Clean
   - Watch
   - Warn
   - Hide in Strict Mode
   - Block in Strict Mode
8. User can create personal blocklist and trustlist.
9. User can export/import settings and reports as JSON.
10. App includes a demo page showing the full product story.
11. App includes a waitlist/pricing page for future monetization.

---

## 4. What This MVP Will NOT Do

The Replit MVP must avoid risky or unreliable features.

Do **not** build:

- A custom search engine.
- Google scraping.
- AI detection using paid APIs.
- AI-generated content classifier.
- Real-time filtering inside Google results page.
- Chrome extension.
- Android APK inside this MVP.
- User accounts.
- Payments.
- Heavy backend.
- Browser automation.

Reason: these are too slow, brittle, expensive, or risky for a 24-hour Replit build.

---

## 5. Key Technical Constraint

A normal website cannot reliably edit or remove content inside `google.com` after redirecting the user, because Google is a different origin.

Therefore, the Replit MVP should behave as:

**AI-free search launcher + domain reputation system + community report prototype**

not as a full browser that modifies Google result pages.

## 9. Risk Score Logic

Risk score must be deterministic and local.

### 9.1 Basic Formula

```ts
riskScore = Math.min(1,
  totalReports * 0.03 +
  aiSlopReports * 0.02 +
  scamReports * 0.06 +
  fakeSupportReports * 0.05 +
  misleadingReports * 0.04
);
```

### 9.2 Tier Rules

```ts
if riskScore >= 0.80 or totalReports >= 75:
  tier = "block_strict"

else if riskScore >= 0.60 or totalReports >= 25:
  tier = "hide_strict"

else if riskScore >= 0.35 or totalReports >= 10:
  tier = "warn"

else if totalReports >= 3:
  tier = "watch"

else:
  tier = "clean"
```

### 9.3 UI Copy by Tier

Clean:
- “No meaningful reports found.”

Watch:
- “A few users have reported this domain. Review carefully.”

Warn:
- “This domain has multiple community reports. Be careful.”

Hide in Strict Mode:
- “Strict Mode would hide this domain by default.”

Block in Strict Mode:
- “Strict Mode would block this domain unless you choose to open it.”

## 11. Domain Normalization Rules

Function name:
`normalizeDomain(input: string): string | null`

Requirements:
- Accept full URLs.
- Accept bare domains.
- Accept copied URLs with spaces.
- Lowercase domain.
- Remove protocol.
- Remove `www.`
- Remove path/query/hash.
- Reject empty input.
- Reject invalid strings.
- Do not crash on malformed input.

Examples:
- `https://www.Example.com/path?a=1` → `example.com`
- `example.com/blog` → `example.com`
- `   HTTPS://WWW.TEST.COM   ` → `test.com`
- `not a url ???` → `null`

---

## 12. Search URL Builder

Function name:
`buildSearchUrl(input: string, engine: SearchEngine): string`

Behavior:
- If input is detected as URL:
  - Return normalized/openable URL with `https://` added if missing.
- If input is search text:
  - Use selected engine.

Search formats:
```ts
google_web:
  https://www.google.com/search?q=<encoded_query>&udm=14

google_normal:
  https://www.google.com/search?q=<encoded_query>

duckduckgo:
  https://duckduckgo.com/?q=<encoded_query>

brave:
  https://search.brave.com/search?q=<encoded_query>
```

Safety:
- Encode query.
- Do not use dangerouslySetInnerHTML.
- Never execute user input.
- Reject javascript: URLs.
- Reject data: URLs.
- Reject file: URLs.

## 22. Final Build Decision

For Replit, build **only the PWA/site MVP**.

Why:
- Fastest to ship.
- No paid APIs.
- No app store.
- No Android build complexity.
- Best for buildathon demo.
- Easy to share with judges.
- Same UI can later be reused inside Android app.

Main demo claim:
**“We are not replacing Google. We are giving users a human-web control layer over search.”**
